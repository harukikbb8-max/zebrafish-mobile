# ローカル攻撃検証レポート(2026-11-15)

同期バックエンド(`src/sync/Code.gs`)とアプリの同期処理(`src/sync/sheets.ts`)について、
コードレビューで見つけた問題をローカル環境で実際に試した記録。6 件すべて再現した。

修正はこのレポートには含まない。対応方針は末尾の「修正案」を参照。

## 検証環境と安全対策

- 攻撃対象は、`src/sync/Code.gs` を無改変で読み込み、Google のサービス(スプレッドシート、
  スクリプトプロパティ、キャッシュ、ロック)をメモリ上の偽物に差し替えたローカルサーバー
  (`http://127.0.0.1:8787/exec`)。
- 本物の GAS、スプレッドシート、配信中のアプリには一切アクセスしていない。
- データはすべてその場で作ったダミー。本物の同期 URL や合言葉は使っていない。
- 6 番だけは、ローカルで起動した Web 版アプリの同期先を上記の偽サーバーに向けて実測した。
  このときアプリの通常動作として天気 API(Open-Meteo)への読み取りが発生する。

## 結果

### 1. 認証なしで全データを読み出し・全削除(重要度: 高)

- 原因: `SECRET` 未設定だと `checkToken` が常に通る(`src/sync/Code.gs:148-152`)。
  デプロイは「アクセスできるユーザー: 全員」。
- 方法: `SECRET` 未設定の状態で、トークンなしの `pull` と、全行に `deleted=1` を立てた `push` を送信。
- 結果: 水槽 2 件をそのまま取得できた。`push` は `applied: 2` で受理され、全行が `deleted=1` になった。

### 2. 未来の時刻で行を上書き不能にする(重要度: 中)

- 原因: Last-Write-Wins がクライアント申告の `updated_at` をそのまま信用する(`src/sync/Code.gs:241`)。
- 方法: `updated_at` を 2099 年にした行(メモ改ざん + 削除フラグ)を送信し、
  その後、正規ユーザーとして現在時刻で修正を送信。
- 結果: 正規の修正は `applied: 0` で無視され、シートは攻撃者の値のまま残った。

### 3. 数式インジェクションで同期対象外のタブを読む(重要度: 高)

- 原因: 受け取った文字列を無加工で `setValues` に渡す(`src/sync/Code.gs:232-235`, `250`)。
  `setValues` は `=` で始まる文字列を数式として扱う。
- 方法: 別タブ「管理メモ」にダミーの機密文を置き、水槽のメモに `=管理メモ!A1` を入れて送信。
- 結果: シートには `=` 始まりのまま保存され、次の `pull` でメモ欄に別タブの機密文が返った。
- 注意: 「`=` 始まりを数式として評価する」部分は、Google の挙動を偽サーバー側で簡易的に真似たもの
  (`=タブ名!A1` 形式の参照のみ)。無加工で保存される点は実コードの動作そのまま。
  本物のスプレッドシート上では試していない。

### 4. 合言葉(SECRET)の総当たり(重要度: 高)

- 原因: 試行回数の制限も失敗時の遅延もない(`src/sync/Code.gs:148-152`)。
  `ping` が合否をそのまま返す(`src/sync/Code.gs:73`)。
- 方法: `SECRET` を弱い単語に設定し、13 語の辞書を `ping` で順に試行。
- 結果: 12 語目で的中した。続けて 1 秒間に 1,133 回試しても一度も拒否されなかった。
- 注意: 速度はローカルでの値。本物の GAS は 1 回あたりがもっと遅い。回数制限がない点は実コードどおり。

### 5. 不正なテーブル名でシートを作る(重要度: 低)

- 原因: スキーマ判定が `SCHEMA[name]` の真偽だけなので、`constructor` などの
  プロトタイプ由来の名前が通る(`src/sync/Code.gs:133-136`)。
- 方法: テーブル名を `constructor` / `toString` / `valueOf` / `hasOwnProperty` にして `push`。
- 結果: 4 つとも同名のシートが作られた(その後の処理は例外で止まり、データは壊れない)。

### 6. 同期ログの自己増殖(重要度: 高、攻撃ではなく通常利用で発生)

- 原因: 自動同期は送信か取込が 1 件でもあると「同期」ログを 1 行書く(`src/sync/sheets.ts:299`)。
  そのログ行自体が次回の送信対象になり(`src/sync/sheets.ts:180`、除外なし)、
  次の同期がまた新しいログ行を生む。
- 方法: Web 版アプリの同期先を偽サーバーに設定し、「餌をあげた」を 1 回だけ押して放置。
- 結果: 操作なしのまま、約 10 秒に 1 行のペースで同期ログが増え続けた。

  | 経過 | `activity_logs` の行数 | うち同期ログ |
  |---|---|---|
  | 15 秒 | 2 | 1 |
  | 30 秒 | 4 | 3 |
  | 60 秒 | 7 | 6 |
  | 105 秒 | 11 | 10 |

  端末 1 台を 8 時間開いたままにすると約 2,900 行増える計算。GAS は書き込みのたびに
  シート全体を読み書きするため、行数が増えるほど同期が遅くなり、いずれ止まる。

## 試していないもの

- GitHub Secrets に `SHEET_URL` / `SHEET_TOKEN` を登録した場合の露出。
  公開されている EAS Update のマニフェストを読み取り、現時点では両方とも空であることだけ確認した。
  登録すると、マニフェスト経由で誰でも取得できる状態になる(`app.config.ts:27-28`)。
- CSV エクスポートの数式インジェクション(`src/lib/csv.ts:5-12`)。コード上の指摘のみ。
- 本物の Google スプレッドシート上での数式の実行。

## 修正案

| # | 修正 | 場所 |
|---|---|---|
| 1 | `SECRET` 未設定なら拒否する | `Code.gs` |
| 2 | 未来の `updated_at` をサーバー時刻に丸める | `Code.gs` |
| 3 | `=` `+` `-` `@` で始まる文字列の先頭に `'` を付けて書く(書き戻す全セルに適用) | `Code.gs` |
| 4 | 合言葉を 32 文字以上のランダム文字列にする。失敗回数を `CacheService` で数えて一時拒否する | `Code.gs` / 運用 |
| 5 | スキーマ判定を `hasOwnProperty` にする | `Code.gs` |
| 6 | 「同期」ログを送信対象から外す | `sheets.ts` |

`Code.gs` を直した場合は GAS の再デプロイ(既存デプロイの編集 → 新バージョン)が必要。

## 再現手順

スクリプトは `docs/security/repro/` にある。すべて `127.0.0.1` 宛てに固定してある。

1. 偽サーバーを起動する。

   ```bash
   node docs/security/repro/mock-gas.js src/sync/Code.gs
   ```

2. 1〜5 を実行する。

   ```bash
   node docs/security/repro/attack.js
   ```

3. 6 を実行する。Web 版の起動(`npx expo start --web`)と Playwright が別途必要。

   ```bash
   node docs/security/repro/loop.js
   ```
